# Arrantza - Design

**Snapshot updated:** 24 September 2026, 19:25 CEST

**Document role:** Canonical consolidated design document. This snapshot merges the previous Master Design and Master Art Direction Guide into one source of truth and incorporates the latest locked prototype decisions from the current design discussion.

The game is a mobile-first, portrait-only fishing game built around a very simple core interaction that can gradually become demanding through creature behaviour, tension management, directional reactions, bosses, and increasingly unusual stages.

The project should stay deliberately lean. Variety should come primarily from creatures, authored stages, atmosphere, and mastery of the fishing system rather than from equipment, inventory, or large numbers of secondary systems.

### Consolidation changes in this snapshot

- The visual direction remains locked to the **hybrid illustrative 2D** system defined in the Art Direction section: graphic cel-shaded gameplay elements plus painterly storybook environments.
- The Player Character is **always seated and viewed from behind** during Stage gameplay.
- The Contextual Main Button is **circular**, not oval.
- Fight indicators remain together in one compact HUD cluster: temporary Directional Run cue, Tension, Catch Progress, then the circular Contextual Main Button.
- The first working prototype should already follow Arrantza's chosen art direction rather than use visually unrelated gray-box/placeholders, while still allowing prototype-quality assets.
- **Stage 1 – Lake now has a locked seven-Creature first-clear roster:** European Perch, Rainbow Trout, Common Carp, Northern Pike, Largemouth Bass, European Eel, and Wels Catfish.
- Prototype tuning values and behavioural identities are now defined for all seven Lake Creatures.
- Creature encounters are **behaviour-driven / semi-authored rather than scripted to exact fight-clock timestamps**. Moves use eligibility ranges, cooldowns, recovery rules, and consistent move timings.
- First-clear teaching encounters may guarantee that a mechanic appears, but the event should occur within an authored range rather than at one fixed second.
- The Wels Catfish boss uses sticky Catch Progress milestones for its behavioural phases: once a later phase is reached, losing Catch Progress does not revert it to an earlier phase.
- **Directional Run**, **Surge**, and **Directional Surge** are now distinct encounter concepts: direction, raw resistance, or both at once.
- The SFX / haptic / UX feedback layer is now defined for the prototype, including sparse event-based vibration patterns, dynamic Tension audio, immediate Release Reel feedback, and Music / SFX / Haptics settings.
- Prototype moment-to-moment UX is now defined: randomized **2–5 second** Waiting Phase, **no fake nibbles in Prototype 1**, approximately **0.9 second** Hook window, fresh-press Hook requirement, explicit gameplay states, touch capture, pause/interruption rules, and missed-Hook handling.
- Prototype shell behaviour is now defined: local browser save, independent per-Stage progression, all Stages available immediately, portrait-only Rotate Device overlay, user-triggered fullscreen, safe-area / thumb ergonomics, mouse fallback, and repeat-European-Perch behaviour for Prototype 1.
- Prototype music behaviour is now defined: separate Title theme, Stage Select continuation/variation, calm Lake music that continues through ordinary fights, gameplay intensity driven primarily by SFX/ambience, and brief event stings rather than constant music switching.
- The pre-Codex art/reference pack is now defined as five items: Lake Stage key art, Player Character reference, fishing props/effects reference, European Perch Catch Reveal art, and a final Fight Screen mockup.
- Prototype UI/menu structure is now defined: restrained game-like Title Screen, illustrated Stage cards with no lock states, a **global Book organized into Stage sections**, simple Settings panel, two button families, compact in-Stage UI, and focused Catch Reveal.
- The Book now has multiple entry routes: a global **Book** button on Stage Select, optional Stage-card shortcuts into a specific Stage section, and in-Stage Book access that jumps directly to the current Stage's section.
- Approved Prototype 1 visual references are now synchronized into the design: Lake-specific chair treatment, tighter recurring-props scope, centered Fight HUD cluster, approved Title Screen structure/logo direction, Stage Select spacing/navigation, and the global Book reference requirements.

## 1. Core Loop

The current core loop is:

1. Choose a fishing stage.
2. Enter the fixed authored stage scene.
3. Cast with one tap.
4. Wait for a creature to bite.
5. Hook the creature.
6. Fight it by reeling, managing line tension, and reacting to directional runs.
7. Either land the creature or lose it when the line snaps.
8. If successful, watch a short generic landing animation.
9. Reveal the caught creature in a popup using a still image.
10. Add or update that creature's entry in the stage Book.
11. Cast again.

The first clear of a stage uses an authored creature sequence rather than random encounters. Stage 1, the Lake, is currently planned around seven creatures encountered in order from easiest to hardest, with the seventh acting as the stage boss.

After a stage has been cleared, revisiting it may use a freer/randomized encounter order from its completed creature roster so that replaying the stage is less predictable.

## 2. Stage Structure and Presentation

The game is designed mobile-first and portrait-only.

The visual direction is now locked to a **hybrid illustrative 2D approach**. Gameplay-critical elements use clean, graphic cel-shaded rendering, while the larger Stage environment uses a painterly storybook treatment. Subtle 2.5D layering or parallax may be used while preserving the appearance of one authored 2D illustration.

Each Stage uses a fixed, authored cinematic angled composition rather than a free-roaming camera or freely controlled character.

### Screen composition

**Bottom-left / lower foreground**
- Always-seated Player Character
- Player Character viewed from behind; face not visible
- Fishing Rod
- Player props where appropriate
- Stage-specific Foreground Setup, including whatever the Player Character is seated on
- The Foreground Setup can change substantially between Stages

**Center / middle**
- Main body of water, liquid, or equivalent fishing surface
- Bobber and Fishing Line
- Most fishing activity
- Water/surface movement and Fight reactions
- Splashes, wakes, ripples, and other Creature-driven effects

**Mid-top / top**
- The rest of the themed Stage environment
- Primarily atmospheric and ambient animation
- Stage-specific scenery, visual identity, and background motion

The Player Character remains clearly visible but does not dominate the composition. The fishing surface and the Stage itself are the visual focus.

Each Stage has one authored version. There is no dynamic day/night or weather system that creates alternate versions of the same Stage. A Stage may itself be rainy, foggy, nighttime, stormy, or otherwise unusual, but that condition is part of the Stage's authored identity.

## 3. Permanent Fishing Setup

The player uses the same basic fishing setup throughout the game.

### Locked
- One fishing rod for the entire game
- One bait for the entire game
- No bait selection
- No bait inventory
- No bait upgrades
- No rod/reel/line equipment ladder
- No percentage-based gear progression

Progression should come from:
- Player mastery
- More difficult creature behaviour
- New stages
- New creatures
- Boss encounters
- Completing the Book
- Reaching increasingly strange parts of the game

A harder creature should be catchable because the player has learned the fishing system, not because they purchased equipment with better stats.

---

## 4. Contextual Main Button

One large **circular** contextual touch button handles the main fishing actions. It should not use an oval/pill silhouette.

Its function changes depending on the current state while remaining in the same primary control location.

### Ready
`CAST`

Pressing it casts automatically to the Stage's fixed Cast Point.

### Casting / Waiting
The main action is inactive. The player cannot pre-hold the control to guarantee a future Hook.

### Real Bite
`HOOK`

A successful Hook requires a **fresh press that begins after the real Bite starts**.

Pre-holding before the Bite must never auto-Hook the Creature.

The player presses and holds the button during the Hook window.

### Fight begins
`REEL`

The transition from Hook to Reel must be seamless.

The player should not need to:

> tap Hook -> release finger -> press Reel again

Instead:

> Creature bites -> button becomes Hook -> player presses and keeps holding -> Hook succeeds -> button immediately becomes Reel under the same finger -> continued hold begins reeling

Once Reel has begun, the active pointer remains captured even if the finger slides outside the circular button. This is necessary for comfortable Directional Input.

Lifting that active finger anywhere ends Reel and performs Give Line / Release Reel.

A second touch does not replace or interfere with the primary active Reel pointer.

### Landing / Line Snap / Catch Reveal
The action button is inactive until the game returns to the ready-to-cast state.

## 5. Casting

Casting is intentionally simple.

- One tap / press of the Cast button
- No casting power meter
- No manual aiming
- No player-selected cast distance
- Each stage has a fixed authored cast point

The purpose of casting is to begin the encounter loop, not to become a separate minigame.

---

## 6. Waiting and Bite

After casting, the Bobber remains in the Stage while the player waits for a real Bite.

### Prototype 1 rules

- The normal Waiting Phase lasts a randomized **approximately 2–5 seconds** after the Bobber lands.
- Prototype 1 uses **no fake Nibbles**.
- A real Bite uses both clear visual and audio feedback.
- The Contextual Main Button becomes `HOOK`.
- The initial Hook reaction window is approximately **0.9 seconds**.
- The Hook should demand attention without becoming a precision rhythm-game input.
- A Hook requires a fresh press that begins after the Bite starts; pre-holding is invalid.
- If the player misses the Hook window, the Creature escapes with brief visual/audio feedback and the game returns to the ready `CAST` state.
- Missing a Hook has no additional punishment.

The exact 2–5 second Waiting range and ~0.9 second Hook window are **prototype starting values** and may be tuned after real-phone testing.

Fake Nibbles remain a future possibility if the Waiting Phase later feels too passive, but they are deliberately excluded from Prototype 1.

## 7. Core Fight System

The current fight system combines a simple hold-to-reel structure with line tension and directional creature runs.

The three main concepts are:

### Catch Progress
How close the creature is to being successfully landed.

### Tension
How much stress is currently being placed on the fishing line.

Too much tension for too long causes the line to snap.

### Direction
Harder creatures can make left/right runs that the player must react to.

---

## 8. Fight Controls

Once the creature is hooked:

### Hold Reel
- Pulls the creature toward the player
- Increases Catch Progress
- Can also increase Tension depending on what the creature is doing

### Release Reel
- Gives the creature line
- Reduces Tension
- Causes Catch Progress to decay while the player is not reeling
- The decay rate is creature-specific: easier creatures lose progress slowly, while stronger creatures can punish releasing much more heavily

### Directional input
During harder encounters, Creatures make discrete left/right Directional Runs.

The player responds **from the same held REEL touch** rather than using separate left/right buttons. Direction is measured relative to the position where the player originally pressed the circular Reel control:

- Keep holding and slide slightly left for a left response.
- Keep holding and slide slightly right for a right response.
- A small dead zone around the original touch position prevents accidental direction changes from normal thumb movement.
- The required drag should be small and comfortable; the player should not need to move across a large part of the screen.
- The player maintains the indicated direction for the duration of the Run rather than performing a one-time directional tap.
- When the Run ends, the thumb can return toward neutral while remaining held.
- If Tension becomes too dangerous, lifting the finger entirely overrides directional play and Gives Line / Releases Reel.

Correct directional response:
- Keeps the Creature under better control
- Reduces or limits the additional Tension caused by the Directional Run
- Allows Catch Progress to continue effectively
- Does **not** make a powerful Creature completely safe to reel against; strong resistance can still force the player to release even while responding correctly

Incorrect, neutral, or late response during a Run:
- Causes significantly more Tension
- Stops effective Catch Progress gain for the current prototype baseline
- Does **not** add a separate arbitrary Catch Progress-loss penalty while Reel remains held; the severe Tension pressure is already the main punishment
- Improves immediately once the player moves into the correct direction; the system behaves continuously rather than as a hidden pass/fail QTE

This creates an important harder-Creature decision: the player may be correctly following a right- or left-side Run while reeling, yet still have to release because Tension is approaching critical. Releasing saves the line but sacrifices Catch Progress. The player then resumes reeling once Tension is under control.

Directional movement is used as readable events/runs rather than constant continuous steering. Later Creatures can use reversals by changing from one direction to the other, forcing the player to move back through neutral while maintaining the Reel hold.

This keeps the interaction close to:

> reel -> react to a run -> manage tension -> resume pushing toward the catch

rather than requiring the player to chase an invisible horizontal coordinate at all times.

### Core risk/reward relationship

The two fight meters should create opposing pressure:

- **Tension is the reason the player must release.**
- **Catch Progress decay is the reason the player cannot release indefinitely.**

Reeling aggressively wins ground but creates danger. Releasing is a tactical sacrifice: it protects the line while giving the creature some ground back.

The intended skill is therefore not simply reacting correctly to left/right cues. Stronger creatures should increasingly test **when to push, when to release, and how efficiently the player can return to reeling after creating a safe Tension margin**.

## 9. Difficulty Progression Through Creature Behaviour

The control scheme does not change as the game becomes harder.

Instead, creatures demand more from the same controls.

### Very easy creatures
- Little meaningful lateral movement
- Low Tension pressure
- Primarily teach holding Reel and making Catch Progress
- Very forgiving Catch Progress decay while Reel is released

### Easy / early creatures
- Stronger resistance
- Begin teaching when to stop reeling and reduce Tension
- Catch Progress still decays slowly enough that defensive play is forgiving

### Intermediate creatures
- Introduce clear left/right directional runs
- Release timing starts to matter more because Catch Progress is lost at a more noticeable rate

### Hard creatures
- Stronger pulls
- More dangerous Tension spikes
- Faster directional reactions
- Fake-outs
- Repeated bursts
- Shorter recovery opportunities
- Faster Catch Progress decay while Reel is released, meaning the player cannot remain defensive for long

### Boss creatures
- Combine multiple behaviours
- Can use aggressive directional runs
- Strong Tension pressure
- Sudden reversals
- Fake-outs
- Multiple behavioural phases if appropriate
- Can heavily punish poorly timed or overly long releases through high Catch Progress decay

The player never needs a new rod, bait, ability, or button to handle this escalation.

## 10. Creature Behaviour Archetypes

Current reusable behaviour concepts include:

### Calm
Steady, low-pressure resistance with little lateral movement.

### Runner
Makes longer directional runs.

### Darter
Uses quick left/right changes but may have less raw strength.

### Heavy
Moves slowly but creates high Tension.

### Thrasher
Produces short, violent bursts separated by calmer windows.

### Fake-out
Appears calm or exhausted before suddenly resisting again.

### Boss
Not necessarily a separate archetype. Boss creatures can combine several of the above behaviours and potentially change behaviour during the fight.

These are design building blocks rather than rigid classes that need to be shown to the player.

### Creature fight tuning parameters

Individual creatures can be differentiated through data rather than new controls. Useful per-creature parameters include:

- **Strength / resistance** — how much pressure the creature applies
- **Tension generation** — how quickly reeling against that creature raises Tension
- **Catch Progress gain rate** — how quickly effective reeling advances the catch
- **Catch Progress decay rate / Release Penalty** — how quickly Catch Progress falls while Reel is released
- **Directional run frequency** — how often left/right runs occur
- **Directional run severity** — how dangerous or demanding those runs are
- **Burst frequency / intensity** — how often the creature produces sudden surges
- **Recovery windows** — how often the player receives safer opportunities to reel
- **Critical Tension pressure** — how difficult it is to recover once Tension becomes dangerous

A key difficulty principle is that stronger creatures can punish defensive play more heavily. Easy creatures allow the player to release for longer with little lost progress; hard creatures and bosses can make every release costly, forcing more precise Tension management.

## 11. Success, Landing, and Catch Reveal

When Catch Progress reaches its success condition, the creature is considered defeated and landing begins automatically.

There is no additional final timing/QTE step.

### Landing
- The player character performs a generic animation of reeling/pulling the catch in.
- The actual creature does not need to be shown during this stage animation.
- This avoids requiring a bespoke in-world landing animation for every creature.

### Reveal
After the landing animation:
- A popup appears.
- The caught Creature is shown using a still image.
- Its identity is revealed here.
- Its Book entry is unlocked or updated.
- Relevant record information can be displayed here if such systems are later retained.

For Prototype 1:
- The European Perch reveal shows its artwork and name.
- The first successful catch also shows **New Book Entry**.
- Repeat Perch catches use the same reveal without the `New` treatment.
- The player dismisses the reveal manually with a simple **Continue** action.
- Size / weight records are **not required** for Prototype 1.

The Creature's catch-reveal artwork can therefore carry much of the visual payoff without requiring every Creature to have extensive bespoke Stage animation.

---

## 12. Failure

The current failure condition is a line snap.

If Tension remains too high, the line snaps and the creature escapes.

After the failure feedback finishes, the player can immediately cast again.

The exact grace period at critical Tension is still to be tuned during prototyping.

---

## 13. Fight UI

The Fight HUD uses one compact, visually grouped cluster so the player does not need to look back and forth between separate areas while simultaneously reading direction, Tension, and Catch Progress.

The current locked hierarchy is:

1. **Temporary Directional Run cue** at the top of the cluster when applicable
2. **Tension Bar** directly below it; thinner and visually secondary to Catch Progress, but clearly readable as danger
3. **Catch Progress Bar** directly below Tension; thicker and the primary victory indicator
4. **Circular Contextual Main Button** below the meters, showing the current CAST / HOOK / REEL state

The exact decorative treatment, typography, textures, iconography, and final proportions may evolve with art production, but the information hierarchy and the decision to keep these indicators together should remain stable.

Physical Stage feedback such as rod bend, Fishing Line pull, Bobber movement, wakes, splashes, and asymmetrical ripples should reinforce Directional Runs and Tension without moving the player's primary directional indicator away from the HUD cluster.

The HUD should remain compact so that the authored Stage remains the visual focus.

## 14. Book / Creature Collection

The Book is a **global Creature compendium organized into Stage-based sections**.

It is not limited to one Stage, but every Creature remains grouped under the Stage where it can be encountered.

### Entry routes

1. **Stage Select — global Book button**
   - Stage Select has a bottom navigation row containing **Back** and **Book**.
   - The Book button opens the full compendium.
   - The player can browse between all available Stage sections.

2. **Stage-card Book shortcut**
   - A Stage card may optionally include a small Book / collection shortcut.
   - Using it opens the Book directly on that Stage's section.
   - This shortcut should remain visually unobtrusive.

3. **In-Stage Book button**
   - While a Stage is in the **READY** state, the Stage UI can expose its Book button.
   - Opening the Book from a Stage jumps directly to that Stage's section.
   - The Book cannot be opened during Casting, Waiting, Bite, Fight, Landing, Line Snap, or Catch Reveal.

### Book structure

The global Book contains one section / tab per Stage, for example:
- Lake
- Swamp
- Frozen Waters

Each Stage section shows:
- Stage name
- Book completion, for example `Lake — 4 / 7`
- All Creature slots assigned to that Stage
- Undiscovered Creatures as silhouettes with `???`
- Discovered Creatures with artwork and name
- Optional detailed entry view when a discovered Creature is selected

Caught Creatures may eventually reveal:
- Still image
- Name
- Possible size range / personal record, if such systems are retained
- Short description / habitat / flavor

### Prototype 1

For Prototype 1:
- The global Book exists even though only the Lake is implemented as a playable Stage.
- The Lake section contains seven Creature slots.
- The European Perch begins as a silhouette / `???` entry.
- The first successful Perch catch reveals its artwork and name permanently in the local save.
- Repeat catches do not create a second entry.
- Opening the Book from the Lake Stage jumps directly to the Lake section.
- Opening the Book from Stage Select opens the full Book interface, initially on the last viewed Stage section or the Lake by default.

Rare Creature variants such as albino, giant, ancient, mutated, golden, or ghost forms remain an earmarked optional idea, not a committed system.


## 15. Stage 1 – Lake

The first Stage is the **Lake**.

It begins grounded and believable. The game's stranger and more surreal content should emerge later rather than being required in Stage 1.

### Locked first-clear Creature roster

The Lake uses seven Creatures in a fixed first-clear order:

1. **European Perch**
2. **Rainbow Trout**
3. **Common Carp**
4. **Northern Pike**
5. **Largemouth Bass**
6. **European Eel**
7. **Wels Catfish — Lake Boss**

The roster is designed as a natural teaching and mastery curve. New controls are introduced sparingly; later Creatures become harder mainly by demanding more precise use of the same Reel, Release Reel, and Directional Input systems.

### Lake Creature behaviour table

All numeric values below are **prototype starting values**, not final balance. They are intended to give implementation something concrete to test and tune.

| # | Creature | Archetype / role | Catch gain | Release decay | Normal Tension gain | Tension recovery | Directional behaviour / special pressure | First-clear guarantee |
|---|---|---|---:|---:|---:|---:|---|---|
| **1** | **European Perch** | Calm — teaches Reel / Release | +13/s | -3/s | +16/s | -50/s | No Directional Runs and no special attacks; steady, forgiving resistance | None required; the whole encounter is the introduction |
| **2** | **Rainbow Trout** | Stronger Calm — reinforces basics | +12/s | -5/s | +20/s | -46/s | No Directional Runs; same core rules with more pressure and a slightly harsher Release Penalty | None; the player should feel that the familiar system is less forgiving |
| **3** | **Common Carp** | Runner — introduces Directional Runs | +11/s | -7/s | +21/s | -43/s | Clear left/right Runs; ~+27/s Tension on correct response, ~+48/s on wrong/neutral response | First Directional Run occurs reasonably early within an authored range |
| **4** | **Northern Pike** | Heavy / Thrasher — Tension pressure | +10/s | -9/s | +25/s | -40/s | Occasional Directional Runs plus sudden resistance surges; ~+34/s correct-run Tension, ~+55/s wrong-run Tension | At least one clearly telegraphed surge before the fight is nearly over |
| **5** | **Largemouth Bass** | Darter / Runner — directional mastery | +10/s | -11/s | +23/s | -39/s | Frequent shorter Runs, quicker reactions, occasional reversals; ~+31/s correct-run Tension, ~+58/s wrong-run Tension | At least one reversal so the player learns that Runs can switch direction |
| **6** | **European Eel** | Fake-out / Thrasher — combined normal-Creature test | +9/s | -14/s | +27/s | -37/s | Irregular calm periods, sudden surges, deceptive directional bursts and fake-outs; ~+36/s correct-run Tension, ~+62/s wrong-run Tension | At least one genuine fake-out after meaningful progress has been made |
| **7** | **Wels Catfish** | Boss — full-system fight | +7.5–8/s | -18/s | +30/s | -34/s | Heavy pressure, Runs, surges, Directional Surges, reversals, fake-outs and phase escalation; ~+42/s correct-run Tension, ~+70/s wrong-run Tension | Successful fight should expose the player to the full learned system |

### Intended learning curve

**European Perch — Creature #1**  
Teaches the core relationship between Reel and Release Reel. Releasing is intentionally cheap and Tension recovery is fast.

**Rainbow Trout — Creature #2**  
Uses the same rules but raises the pressure. The player learns that the Reel / Release rhythm has to become more deliberate.

**Common Carp — Creature #3**  
Introduces Directional Runs with generous timing and clear cues.

**Northern Pike — Creature #4**  
Makes Tension management the main threat. Sudden surges can force the player to Give Line even outside a Directional Run.

**Largemouth Bass — Creature #5**  
Tests quicker Directional Inputs and introduces reversals. Its difficulty comes more from movement complexity than pure raw strength.

**European Eel — Creature #6**  
The first genuinely difficult normal Creature. It combines learned systems with deceptive calm periods and readable fake-outs.

**Wels Catfish — Creature #7 / Boss**  
Combines the entire Lake ruleset into a longer, phase-based fight. Correct Directional Input improves control but does not make the Creature safe to reel against indefinitely.

### Shared Directional Run rules

For every Creature using Directional Runs:

**Correct Directional Input while holding Reel**
- Catch Progress continues at roughly **65–75% of that Creature's normal Catch Progress gain rate** as a starting target.
- Tension rises at that Creature's correct-run Tension rate.
- A sufficiently powerful Creature may still force the player to Release Reel despite a correct response.

**Wrong, neutral, or late Directional Input while holding Reel**
- Catch Progress gain stops for the current prototype baseline.
- Tension rises at the Creature's much higher wrong-run rate.
- There is no additional arbitrary Catch Progress decay simply for holding the wrong direction in the initial implementation.
- Moving into the correct direction immediately improves the situation; this is a continuous system rather than a binary QTE.

**Release Reel during a Directional Run**
- Direction temporarily stops mattering while Reel is released.
- Tension falls according to the Creature's normal Tension recovery.
- Catch Progress decays according to that Creature's Release Penalty.
- Re-engaging Reel returns the player to Directional Input if the Run is still active.

### Directional Run vs Surge vs Directional Surge

These terms describe different parts of Creature resistance and should not be treated as synonyms.

**Directional Run**
- The Creature pulls clearly left or right.
- A Directional Run requires matching Directional Input while the player continues to hold Reel.
- The main question is **which way the Creature is pulling**.

**Surge**
- The Creature suddenly applies much stronger resistance.
- A Surge does **not** inherently require left/right Directional Input.
- Its main effect is increased Tension pressure, usually with stronger rod, line, water, audio, and haptic feedback.
- The player may need to Release Reel to survive it.

**Directional Surge**
- A Directional Run and Surge happen together.
- The player must match the left/right direction while also managing unusually high Tension pressure.
- Correct Directional Input improves control but may still leave Tension rising fast enough that Release Reel is necessary.
- This is especially suitable for powerful late Creatures and the Wels Catfish Boss.

This separation gives the encounter system more variety without adding another control.

### Move timing and cooldown starting ranges

These values define **move behaviour**, not fixed timestamps on the global fight clock.

| Creature | Prototype move timing |
|---|---|
| **Common Carp** | Directional Run becomes eligible after roughly **2–3 seconds** of ordinary fighting; reaction window **0.8–1.0 s**; Run duration **1.5–2.0 s**; Run cooldown roughly **2.5–4.0 s** |
| **Northern Pike** | Surge telegraph roughly **0.35–0.55 s**; surge duration roughly **0.6–1.0 s**; surge cooldown roughly **2.5–4.0 s**; Directional Runs are less frequent than the Carp's |
| **Largemouth Bass** | Reaction window roughly **0.55–0.70 s**; individual Run segments roughly **0.8–1.4 s**; directional-event cooldown roughly **1.8–3.0 s**; some Runs may reverse once |
| **European Eel** | Fake-out tell roughly **0.3–0.5 s**; sudden resistance event roughly **0.7–1.1 s**; calm/recovery periods typically **1–2 s**; after roughly two demanding events, provide a recovery opportunity rather than chaining pressure indefinitely |
| **Wels Catfish** | Move frequency and combinations depend on the active boss phase; early cues and recovery are more generous, while later phases shorten recovery and permit more complex combinations without making individual cues inconsistent or unreadable |

### Encounter behaviour philosophy

Creature moves are **not** scripted to exact elapsed fight times such as:

> 10.0 seconds -> right Run  
> 14.0 seconds -> surge  
> 19.0 seconds -> left Run

Instead, each Creature uses a small behaviour pool controlled by rules such as:

- Current Catch Progress
- Current Tension
- Active boss phase, where applicable
- Previous move
- Move cooldowns
- Minimum recovery rules
- Whether a first-clear teaching guarantee still needs to occur
- Which behaviours are currently eligible

The system selects from the behaviours that are valid at that moment.

This creates encounters that are authored in personality but not identical in choreography. Two fights against the same Creature can use different sequences while still feeling unmistakably like that Creature.

A first-clear teaching encounter may force a mechanic to appear — for example, the Common Carp must show the player a Directional Run — but it should happen inside an authored timing range rather than at one exact second.

Once a move begins, its own timing should remain consistent enough for the player to learn:
- Telegraph duration
- Reaction window
- Run / surge duration
- Recovery window
- Critical Tension grace

### Wels Catfish boss phases

The Wels Catfish changes behaviour primarily through **Catch Progress milestones rather than elapsed fight time**.

| Phase | Activation | Behaviour |
|---|---|---|
| **Phase 1** | Start of fight | Heavy and intimidating but readable; longer recovery windows; straightforward Directional Runs establish the boss's strength |
| **Phase 2** | First reaches **35% Catch Progress** | More frequent surges and directional pressure; reversals become possible; recovery windows shorten |
| **Phase 3** | First reaches **70% Catch Progress** | Most aggressive state; fake-outs, stronger Runs, reversals and shorter opportunities to reel safely |

Boss phases are **sticky milestones**.

Once Phase 2 or Phase 3 has activated, losing Catch Progress does not return the Wels to an earlier phase. For example, if the player reaches 72% Catch Progress and is then pushed back to 55%, the Wels remains in Phase 3.

This prevents intentionally or accidentally losing progress from making the boss easier again.

## 16. First-Clear and Replay Structure

### First clear
The stage uses a simple authored progression:

`Creature 1 -> Creature 2 -> Creature 3 -> Creature 4 -> Creature 5 -> Creature 6 -> Creature 7 / Boss`

Once a creature has been successfully caught, the next cast advances to the next creature in the sequence.

This avoids:
- Encounter RNG frustration
- Grinding for rare required creatures
- Difficulty appearing in the wrong order
- Complicated encounter tables during the main progression

### Replay
After clearing the Stage, its completed Creature Roster can use a looser/randomized encounter order.

This allows completed Stages to remain replayable without forcing the player through the exact same seven-Creature sequence every time.

The exact replay-selection rules do not need to be finalized for the first prototype.

### Stage availability and independent progression

Stages are **not globally unlocked through a linear campaign**.

When multiple Stages exist:
- All available Stages are selectable immediately by a new player.
- Each Stage maintains its own independent First Clear progression.
- Entering an untouched Stage begins at that Stage's Creature #1.
- Leaving one Stage and playing another does not reset either Stage.
- Returning to a partially completed Stage resumes from its own next required Creature.
- Completing one Stage is not required to enter another.
- A newly added Stage should simply appear as available and begin at its own Creature #1.

Example with three Stages:

- Lake — next required Creature #4
- Swamp — next required Creature #2
- Frozen Waters — next required Creature #6

All three remain directly selectable.

This means Arrantza's progression is primarily **within each Stage**, not through locking and unlocking whole Stages.

The game begins somewhere mundane and believable.

Later stages can become increasingly unusual.

Possible broad directions include:
- Swamp

- Volcanic or otherwise hostile liquid

The first implementation does not need the entire seven-Creature Lake roster to be fully playable.

- One-tap fixed-point Cast

### Gameplay state machine

Prototype 1 should behave as an explicit state flow:

`READY -> CASTING -> WAITING -> BITE -> FIGHT -> LANDING / LINE_SNAP -> REVEAL / FAILURE -> READY`

Supporting overlay/menu states include:
- Settings / Pause
- Rotate Device
- Resume after browser/app interruption
- Book while READY

Gameplay timers and fight logic should not continue underneath a paused state.

### Pause and interruption behavior

- Opening Settings pauses the current encounter completely.
- If the page becomes hidden, the browser loses focus, or the app is backgrounded, gameplay timers and fight state pause.
- Returning from an interruption must not immediately resume into active danger.
- A simple paused/resume state should let the player consciously continue.

### Orientation

Arrantza remains portrait-only.

If the device enters landscape:
- Pause gameplay.
- Show a simple **Rotate Device** overlay.
- Restore the previous state when portrait orientation returns and the player resumes.

### Fullscreen

Fullscreen is **user-triggered**, never forced automatically.

It may be accessible from the Title Screen and Settings.

### Local save

Prototype 1 uses a local browser/device save.

At minimum save:
- Book discoveries
- Independent per-Stage First Clear progression
- Music setting / volume
- SFX setting / volume
- Haptics setting
- Other small interface preferences where practical

There is no required account, backend, or cloud save.

The local save is specific to the current browser/device and may be lost if site data is cleared or if the player uses an ephemeral/private browser configuration that discards storage.

### Desktop development fallback

Mouse input should emulate the core touch interactions so the game can be developed and tested conveniently on desktop.

Touch remains the intended player input.

### Mobile ergonomics

- Respect device safe areas.
- Keep the circular Contextual Main Button comfortably reachable by thumb.
- Do not place critical controls flush against system gesture regions.
- The Fight HUD must remain readable without obscuring the authored Stage.

### Prototype success question

> Does Cast -> Waiting -> Bite -> Hook -> Reel / Release -> Catch / Fail feel satisfying, readable, responsive, and worth building the rest of Arrantza around on an actual phone?

If that works, additional Creatures, Stages, balance, and content can be layered onto the proven core.

## 22. Game Lingo / Terminology

Use the following terms consistently throughout design discussion, documentation, and implementation.

| Term | Definition |
|---|---|
| **Stage** | One authored fishing location/map, such as the Lake. Each stage has its own environment, foreground setup, creature roster, Book, and progression sequence. |
| **Creature** | Universal term for anything that can be caught. This replaces the generic use of “fish,” because later stages may contain non-fish aquatic or surreal creatures. |
| **Boss Creature** | The final and hardest creature in a Stage's first-clear sequence. Bosses can combine several behaviour archetypes and may use multi-phase behaviour. The Lake Boss is the Wels Catfish. |
| **Creature Roster** | The full set of Creatures assigned to a Stage. The locked Lake first-clear roster is European Perch, Rainbow Trout, Common Carp, Northern Pike, Largemouth Bass, European Eel, and Wels Catfish. |
| **First Clear** | The player’s first progression through a stage. Creatures appear in a fixed authored order from easiest to hardest, ending with the boss creature. |
| **Replay** | Returning to a stage after completing its first clear. Replay may use a looser/randomized encounter order from the completed creature roster. |
| **Cast** | The one-tap action that places the line into the water at the stage’s fixed cast point. |
| **Cast Point** | The predetermined location in the stage where the cast lands. The player does not manually aim or select distance. |
| **Waiting Phase** | The period after casting and before a real bite occurs. |
| **Nibble** | A small pre-bite bobber or line reaction. Fake nibbles are still optional and not yet locked. |
| **Bite** | The real moment when a creature takes the bait. It should be signalled with both visual and audio feedback. |
| **Hook** | The contextual main-button state used when a real bite occurs. The player presses and holds Hook to start the fight. |
| **Reel** | The contextual main-button state during a fight. Holding Reel pulls the creature closer and increases Catch Progress. |
| **Give Line / Release Reel** | Releasing the Reel input during a fight. This lowers Tension but causes Catch Progress to decay. How quickly it decays depends on the creature. |
| **Fight** | The main gameplay phase after a successful Hook and before either Landing or Line Snap. |
| **Catch Progress** | The underlying measure of how close the player is to successfully landing the creature. It increases through effective reeling, decays while Reel is released, and reaches the success condition at full completion. |
| **Catch Progress Bar** | The thicker primary victory meter in the compact Fight HUD cluster. It shows how close the Creature is to Landing. |
| **Catch Progress Decay Rate** | A per-creature value controlling how quickly Catch Progress is lost while Reel is released. Higher values make defensive play more costly. |
| **Release Penalty** | Design shorthand for the Catch Progress lost while giving line. Stronger creatures can have a harsher Release Penalty than easier creatures. |
| **Tension** | The amount of stress currently being placed on the fishing line. Reeling during strong resistance or reacting incorrectly to a directional run increases Tension; releasing Reel lowers it. |
| **Tension Bar** | The thinner danger meter in the compact Fight HUD cluster, positioned directly above Catch Progress. |
| **Critical Tension** | The dangerous upper end of the Tension range. Remaining at excessive Tension for too long causes the line to snap. |
| **Line Snap** | The current failure condition. The fishing line breaks due to excessive Tension and the creature escapes. |
| **Directional Run** | A discrete left- or right-moving struggle event used by harder creatures. The player reacts by dragging/holding toward the indicated direction while reeling. |
| **Directional Input** | The player’s left/right response during a Directional Run. Correct input controls Tension and preserves reeling effectiveness; incorrect input makes the fight more dangerous. |
| **Surge** | A short period of sharply increased Creature resistance that creates a temporary spike in Tension pressure without requiring a new control. |
| **Directional Surge** | A combined event in which a Creature performs a Directional Run while also applying unusually high raw resistance. The player must match direction, but may still need to Release Reel because correct Directional Input does not eliminate the Tension pressure. |
| **Telegraph** | A readable visual and/or audio warning immediately before a demanding move such as a surge, fake-out, or directional change. |
| **Recovery Window** | A calmer period after demanding behaviour in which the player has a safer opportunity to reel and rebuild Catch Progress. |
| **Behaviour Pool** | The set of currently eligible Creature behaviours from which the encounter system can choose based on rules, cooldowns, current meters, previous moves, and phase. |
| **Boss Phase** | A persistent escalation state used by a Boss Creature. The Lake Boss phases are activated by first reaching specific Catch Progress milestones and do not deactivate if Catch Progress later falls. |
| **Behaviour Archetype** | A reusable creature-fight pattern used as a design building block, such as Calm, Runner, Darter, Heavy, Thrasher, or Fake-out. |
| **Calm** | A behaviour archetype with steady, low-pressure resistance and little lateral movement. |
| **Runner** | A behaviour archetype focused on longer directional runs. |
| **Darter** | A behaviour archetype focused on quick left/right changes rather than raw pulling strength. |
| **Heavy** | A behaviour archetype that moves more slowly but produces strong Tension pressure. |
| **Thrasher** | A behaviour archetype that produces short, violent bursts separated by calmer windows. |
| **Fake-out** | A behaviour archetype that appears calm or exhausted before suddenly resisting again. |
| **Landing** | The successful end of a fight after Catch Progress reaches its success condition. Landing begins automatically; there is no final QTE. |
| **Landing Animation** | A generic player-character animation showing the character finishing the catch. The actual creature does not need to appear in-world during this animation. |
| **Catch Reveal** | The popup shown after Landing. It reveals the creature using a still image and can display its name, record information, and Book update. |
| **Book** | The global Creature compendium, organized into Stage-based sections. It can be opened from Stage Select, optionally from a Stage-card shortcut, or from within a Stage. Opening it from a Stage jumps directly to that Stage's section. |
| **Silhouette** | The hidden visual representation of an undiscovered creature in the Book before its first successful catch. |
| **Record** | The player’s best recorded catch value for a creature, such as largest size, if size tracking is retained. |
| **Contextual Main Button** | The large circular primary touch control whose function changes with game state: Cast -> Hook -> Reel. |
| **Fixed Authored Composition** | The locked presentation approach where each stage uses one deliberately composed portrait scene instead of free camera or free-roaming character movement. |
| **Foreground Setup** | The lower-left/lower Stage area containing the always-seated Player Character, Fishing Rod, nearby props, and whatever the Player Character is seated on. This can differ substantially by Stage. |
| **Stage Completion** | Reaching and successfully catching the stage’s boss creature during First Clear. |

## 23. Current Prototype Fight Baseline

These values are **implementation starting values for Creature #1, the European Perch**, intended for feel-testing rather than final balance. They are deliberately forgiving so the first encounter teaches the relationship between Catch Progress and Tension.

| Prototype rule | Starting value |
|---|---:|
| Catch Progress start | 0 |
| Catch Progress gain while reeling | +13 per second |
| Catch Progress decay while Reel is released | -3 per second |
| Tension start | 0 |
| Tension gain while reeling | +16 per second |
| Tension recovery while Reel is released | -50 per second |
| Critical Tension begins | 90 |
| Maximum Tension | 100 |
| Line Snap grace at maximum Tension | approximately 0.8 seconds |
| Landing condition | Catch Progress reaches 100 |

### Creature #1 teaching goal

The **European Perch** is a **Calm / beginner encounter** with no Directional Runs. It exists to teach one relationship:

> Hold Reel to gain Catch Progress and create Tension; release Reel to rapidly relieve Tension while sacrificing a small amount of Catch Progress.

At the initial values, releasing is intentionally cheap. Later Creatures can become harder by changing the relationship between Catch Progress gain, Release Penalty, Tension generation, recovery opportunities, and Directional Runs.

### Meter response

- Catch Progress and Tension respond mechanically as soon as the input state changes.
- When Reel is released, Catch Progress begins moving backward immediately while Tension begins recovering immediately.
- Visual interpolation may be very slight for smooth rendering, but it should not create a noticeable delay between player input and meter response.
- Stronger Creatures may use much harsher Catch Progress decay than Creature #1; this is a major difficulty lever.

### Prototype feedback direction

Continuous meter movement should do most of the ongoing visual communication. Audio and haptics are reserved primarily for meaningful physical events, danger transitions, and state changes rather than constant beeping or vibration.

The detailed prototype feedback map, haptic vocabulary, Tension-audio behavior, Release Reel response, and accessibility/fallback rules are defined in **Section 24 — SFX, Haptics, and UX Feedback**.

## 24. SFX, Haptics, and UX Feedback

The feedback layer is part of the fishing mechanic rather than decorative polish. The player should be able to understand important changes through a combination of **visual response, sound, and optional haptics** without any one channel carrying essential information by itself.

### Core feedback principles

- **Continuous actions are communicated mainly through animation and sound.**
- **Haptics emphasize discrete events, physical impacts, danger transitions, and state changes.**
- Do not vibrate continuously during normal reeling.
- Repeated sounds and haptics should remain restrained enough that long play sessions do not become tiring.
- Every important gameplay event must remain understandable with haptics disabled or unavailable.
- Feedback should feel physically connected to the Fishing Rod, Fishing Line, Bobber, fishing surface, Creature resistance, or player input rather than like generic phone notifications.

### Feedback map

The following values are prototype starting points and should be tuned on real devices.

| Event | SFX direction | Haptic starting pattern | Visual / UX response |
|---|---|---|---|
| **Cast press** | Short rod / line swish | `10 ms` | Immediate button response; Cast animation starts |
| **Bobber lands** | Soft, distinct plop / splash | `15 ms` | Localized ripple at Cast Point |
| **Waiting Phase** | Stage ambience, water, subtle environmental audio | None | Calm authored ambient motion |
| **Nibble** if retained | Tiny plip / tick clearly weaker than a real Bite | `8–10 ms` or none | Small Bobber twitch |
| **Real Bite** | Strong splash plus a sharp recognizable Bite cue | `30 ms` | Strong Bobber movement; Contextual Main Button becomes Hook |
| **Hook success** | Tight tug / rod-load / line-catch sound | `[18, 25, 28]` | Rod loads; Fight HUD appears; button becomes Reel under the held finger |
| **Normal Reel** | Quiet looping reel mechanism plus line / water resistance | None | Catch Progress rises; rod and line respond continuously |
| **Release Reel** | Reel loop stops immediately; brief spool / line-out sound | None | Tension begins falling immediately; Catch Progress begins decaying immediately |
| **Directional Run starts** | Short struggle / water accent | `20 ms` | Directional cue appears in the compact Fight HUD cluster |
| **Correct Directional Input acquired** | No celebratory chime; strain sound simply settles | `8–10 ms` once | Directional cue may visually confirm correct acquisition |
| **Wrong / neutral Directional Input** | Sharper line strain, reel resistance, stronger water turbulence | No repeated buzz by default | Tension rises rapidly; cue remains readable |
| **Surge** | Strong water hit, line strain, rod creak | `30–40 ms` | Stronger rod bend and localized disturbance |
| **Directional Surge** | Directional struggle accent plus stronger strain layer | `35–45 ms` or a short two-pulse pattern for major events | Directional cue remains active while physical feedback shows unusually high resistance |
| **Tension enters warning range** | Subtle additional line / rod strain layer | `18 ms` once | Tension UI becomes more urgent |
| **Critical Tension begins** | High strain / line-whine layer | `[22, 45, 22]` | Strong Critical Tension warning |
| **Critical Tension persists** | Continuing strain; do not spam separate warning sounds | Brief pulse about every `0.4–0.5 s`, rate-limited | Danger remains visually obvious |
| **Snap grace nearly exhausted** | Distinct near-breaking line sound | `[30, 30, 45]` | Final urgent warning before Line Snap |
| **Line Snap** | Sharp crack / twang followed by recoil and abrupt release of strain | `70–80 ms` | Fishing Line breaks; Rod recoils; failure resolves quickly |
| **Catch Progress reaches 100** | Resistance resolves immediately | `[18, 30, 30]` | Automatic Landing begins |
| **Landing** | Reel finish plus splash / pull-in sound | Small finishing pulse if useful | Generic seated finishing animation |
| **Catch Reveal** | Restrained discovery / reveal sting | `20 ms` | Still Creature artwork appears and Book updates |

### Haptic vocabulary

Web haptics should use **duration and rhythm** as the primary design language rather than assume precise actuator-strength control across devices.

Approximate design weights:

- **Tiny: 8–12 ms** — button confirmation, Directional Input acquired, optional Nibble
- **Light: 15–25 ms** — Bobber impact, Directional Run start, warning transition
- **Medium: 30–45 ms** — Bite, Hook connection, Surge, Directional Surge
- **Heavy: 60–80 ms or short multi-pulse patterns** — Line Snap, severe Critical Tension warning, major Boss impact

These are categories for consistency, not promises of identical physical intensity across phones.

### Haptic spam prevention

- Normal Reel has **no continuous vibration**.
- Release Reel has **no vibration by default**.
- Wrong Directional Input should not create a continuous or rapidly repeating buzz.
- Correct Directional Input confirmation happens once when the correct zone is acquired.
- If the player leaves the correct zone and re-acquires it, another confirmation may occur only after a short cooldown.
- Persistent Critical Tension pulses must be rate-limited.
- Boss encounters may use stronger patterns, but should not vibrate continuously simply because the Boss is powerful.

### Dynamic Reel and Tension audio

Normal reeling should not use one flat sound at every pressure level.

The Fight audio should be layered so that increasing Tension can gradually introduce:

- Stronger Fishing Line strain
- Rod creak
- Reel resistance
- More aggressive fishing-surface disturbance
- A restrained higher-frequency stress component near Critical Tension

At low Tension, the player mainly hears the reel mechanism, water, and ambient Stage sound.

This allows the player to **hear rising Tension** without requiring constant visual attention to the meter.

### Release Reel feedback

Release Reel must feel instantaneous.

When the player's finger lifts:

1. Reel audio stops immediately.
2. A short line-out / spool response may play.
3. Tension begins recovering immediately.
4. Catch Progress begins decaying immediately.
5. Rod / Fishing Line pressure visibly eases.

There should be no perceptible delay that makes the player wonder whether the release was registered.

### Directional feedback

Directional Runs remain part of the single compact Fight HUD cluster with Tension and Catch Progress. The player should not need to scan between distant parts of the screen to compare direction, Tension, and progress.

Rod movement, Fishing Line angle, Bobber movement, wake direction, splashes, and other Stage reactions may **reinforce** the indicated direction, but they do not replace the HUD cue.

Correct Directional Input should not produce repeated celebratory sounds. The improved strain sound, tiny one-off haptic confirmation, physical animation, and Tension behavior are enough.

### Critical Tension escalation

Critical Tension should escalate in recognizable steps rather than switching directly from safe to Line Snap.

Prototype hierarchy:

- **Normal / lower Tension:** ordinary Reel and resistance feedback
- **Warning range:** visual urgency plus a subtle strain layer and one light haptic transition
- **Critical Tension:** distinctive visual state, stronger strain audio, and a recognizable double-pulse haptic
- **Critical persists:** sparse, rate-limited warning pulses
- **Snap grace almost exhausted:** final urgent audio / haptic warning
- **Line Snap:** sharp failure sound and strongest single failure haptic

Exact Tension thresholds remain tunable; the established prototype baseline begins Critical Tension at approximately `90 / 100`.

### Music and ambience behavior

Prototype 1 uses a restrained music structure.

- **Title Screen:** its own short looping theme.
- **Stage Select:** may continue the Title theme or use a very light variation rather than requiring another full track.
- **Lake:** one calm ambient music loop.
- **Ordinary Fight:** do **not** switch into separate battle music when the European Perch bites. Lake music continues while the Fight becomes more intense through Reel, water, line, rod, Creature-resistance, and Tension SFX.
- **Catch / Line Snap:** may use a brief sting or resolving accent, then settle naturally back into the Lake soundscape.
- **Boss music:** remains open for later design and is not required for Prototype 1.

Important gameplay cues such as Bite, Critical Tension, Line Snap, and Catch should cut through the mix through prioritization and brief **ducking** of music / ambience where useful rather than simply making every important sound extremely loud.

Frequently repeated sounds should avoid obvious repetition:
- Use small variation sets where practical, such as several Cast swishes or splash sounds.
- Small pitch / timing variation may be used subtly.
- The Reel sound should loop cleanly and stop immediately on Release Reel.

The intended hierarchy is:
1. Critical gameplay cues must always remain readable.
2. Ordinary fishing SFX remain clear but restrained.
3. Stage ambience gives the scene physical presence.
4. Music supports mood without masking gameplay information.

### Audio and haptic settings

The prototype should expose simple user controls for:

- **Music volume**
- **SFX volume**
- **Haptics on / off**

Haptics are optional enhancement only. On devices or browsers where vibration is unavailable, Arrantza must remain fully playable and readable through visual and audio feedback.

### Feedback-system implementation principle

Creature logic should not directly own audio and vibration details.

Gameplay should emit semantic events such as:

- `CAST`
- `BOBBER_LAND`
- `BITE`
- `HOOK_SUCCESS`
- `REEL_START`
- `REEL_RELEASE`
- `DIRECTIONAL_RUN_START`
- `DIRECTION_ACQUIRED`
- `SURGE_START`
- `DIRECTIONAL_SURGE_START`
- `TENSION_WARNING`
- `CRITICAL_TENSION`
- `SNAP_IMMINENT`
- `LINE_SNAP`
- `LANDING`
- `CATCH_REVEAL`

A centralized feedback layer can then decide which SFX, haptic pattern, and visual accent accompanies each event.

This keeps Creature behaviour data-driven and prevents feedback logic from being scattered through individual encounters.

## 25. Master Art Direction


This section is the consolidated visual source of truth for Arrantza. Where a visual implementation question overlaps with general Game Design, both sections should be read together; the specific art-direction rules below govern visual execution.

### AD1. Core Visual Identity

Arrantza uses a **locked hybrid illustrative 2D art direction** combining:

1. **Graphic cel-shaded gameplay elements**
2. **Painterly storybook environments**

Gameplay-critical elements should remain clean, readable, structurally simple, and animation-friendly.

The larger Stage should provide atmosphere, visual identity, scenic richness, and character.

The intended result is a **living illustrated fishing world**.

---

### AD2. Core Visual Rule

The primary rule is:

> **The closer an element is to active gameplay, the cleaner and more graphic it becomes. The farther it is from active gameplay, the more painterly and atmospheric it becomes.**

This preserves gameplay readability while allowing the Stage to remain visually rich.

---

### AD3. Fixed Authored Composition

Every Stage uses the same broad composition.

#### Lower-left / lower foreground

Contains:

- Seated Player Character
- Fishing Rod
- Stage-specific Foreground Setup

The Player Character is always seated.

The Player Character is always viewed from behind.

The Player Character's face is therefore never visible.

---

#### Center

Contains the main:

- Water
- Liquid
- Or equivalent fishing surface

This is where most fishing activity occurs.

It contains or communicates:

- Bobber
- Fishing Line
- Ambient surface movement
- Splashes
- Wakes
- Ripples
- Fight reactions
- Creature-driven disturbances

---

#### Mid-top / top

Contains the larger Stage environment.

This area primarily establishes:

- Atmosphere
- Scenic identity
- Environmental storytelling
- Distant ambient motion
- Major landmarks

The Stage itself should remain the visual focus rather than the Player Character.

---

### AD4. Player Character

The Player Character is persistent across the entire game.

The character is always:

- Seated
- Seen from behind
- Positioned in the lower-left / lower foreground
- Clearly visible
- Secondary to the Stage vista

The Player Character never switches to a standing or front-facing presentation within the Stage composition.

---

### AD5. Player Character Appearance

The Player Character should remain fundamentally recognizable throughout the game.

Clothing and appearance may change slightly depending on the Stage.

These changes should remain restrained.

The purpose is to allow some Stage-specific adaptation without creating a completely different character asset set for every Stage.

Examples of acceptable variation may include:

- Minor clothing layer changes
- Small accessories
- Slight material or color changes
- Stage-appropriate protective additions

The basic character identity, silhouette, seated presentation, and implementation structure should remain stable.

---

### AD6. Player Character Rendering

Use:

- Strong silhouette
- Simplified proportions
- Clear pose
- Large readable clothing shapes
- Flat local colors
- Deliberate cel-shadow groups
- Restrained outlines
- Limited texture

Avoid:

- Visible facial features
- Hyper-anime facial design
- Highly glossy rendering
- Dense costume ornament
- Excessive realistic shading
- Painterly edges that make animation difficult to control

---

### AD7. Foreground Setup

The **Foreground Setup** is Stage-specific and fully flexible.

It includes:

- Whatever the Player Character is sitting on
- Immediate surrounding foreground environment
- Nearby Stage-specific structures
- Terrain
- Vegetation
- Architecture
- Machinery
- Props where appropriate

The entire Foreground Setup may change substantially between Stages.

The Player Character may therefore be seated on completely different things depending on the Stage.

Examples may include:

- Jetty
- Rock
- Boat
- Concrete canal edge
- Flooded masonry
- Industrial structure
- Mechanical platform
- Floating object
- Impossible surreal surface

These are illustrative examples only.

They are not recurring requirements.

---

### AD8. Recurring Visual Elements

The only elements guaranteed to recur across every Stage are:

- Player Character
- Fishing Rod
- Fishing Line
- Bobber

Do not introduce other permanent companions, props, decorations, or environmental objects unless separately established by the design.

---

### AD9. Fishing Rod

The Fishing Rod is a persistent gameplay element.

It should remain readable during:

- Cast
- Hook
- Reel

### AD43. Avoiding BOTW / TOTK / Genshin Similarity

- Painterly noise around the Fishing Line or Bobber

The animated gameplay layer should remain simple enough to implement reliably.

### AD51. Final Art Direction Statement

> Arrantza uses a scalable hybrid illustrative 2D art direction combining clean cel-shaded gameplay elements with painterly storybook environments. Every Stage uses the same Fixed Authored Composition: the Player Character is always seated and viewed from behind in the lower-left/lower foreground, the water, liquid, or equivalent fishing surface occupies the center, and the larger Stage vista occupies the mid-top/top. The Player Character remains fundamentally consistent, with only slight Stage-specific appearance or clothing changes. The complete Foreground Setup—including what the Player Character sits on and the immediate surrounding foreground—may vary freely between Stages. The Fishing Rod, Fishing Line, and recognizable Bobber remain recurring gameplay elements. Gameplay-critical elements use simplified forms, strong silhouettes, restrained outlines, flat local colors, and deliberate cel-shadow grouping, while larger environments use softer painterly rendering, atmospheric depth, designed scenic forms, controlled brush texture, and Stage-specific palettes. The fishing surface bridges both systems, remaining graphic and readable around the active fishing interaction while becoming more painterly and atmospheric toward the surrounding vista.

## 26. Prototype UI and Menu UX

Arrantza's interface should feel like part of a game rather than a generic mobile application.

The authored Stage artwork remains visually dominant.

### UI language

Use:
- Clean readable typography with some character
- Simple illustrated icons
- Softly textured / illustrated panels
- Restrained borders
- Controlled texture
- Short, readable labels
- Consistent visual hierarchy

Avoid:
- Generic app-dashboard presentation
- Excessive glossy effects
- Heavy fantasy ornament
- Large permanent overlays
- Repeated generic rounded cards for every element
- UI that visually competes with the Stage

### Button families

Arrantza uses two broad control families.

**Gameplay control**
- Large
- Circular
- Highly readable
- Used for `CAST -> HOOK -> REEL`
- Visually and physically distinct from menu navigation

**Menu / navigation controls**
- Rectangular or soft-cornered buttons
- Compact icon buttons where appropriate
- Do not mimic the large circular gameplay control unless there is a strong reason

### Title Screen

Prototype 1 Title Screen uses the approved portrait 9:16 reference direction.

It should contain:
- Arrantza title / logo
- No Player Character / angler
- No `A FISHING GAME` subtitle
- Prominent **Play** action
- **Settings**
- **Full Screen** directly below Settings
- No duplicate top-right Fullscreen icon
- Scenic Arrantza presentation rather than a dense menu

The current logo direction uses a paired / double-fish emblem above the `ARRANTZA` wordmark. The upper fish is a darker blue distinct from the wordmark's darkest navy; the lower fish is a lighter blue distinct from the sky/background blue. The emblem should feel naturally integrated into the overall composition.

The Title Screen should feel calm and visually inviting.

### Stage Select

Stage Select uses **large illustrated Stage cards / panels** rather than a spreadsheet-like list.

Each Stage card can show:
- Stage artwork
- Stage name
- Book completion, such as `3 / 7`
- A lightweight First Clear progress indicator if useful
- An optional small Book / collection shortcut that opens the Book directly on that Stage's section

There are **no lock icons for normal Stage availability**.

When three Stages exist, a fresh player can immediately choose any of the three. Each begins at its own Creature #1 and progresses independently.

Leave clear vertical breathing room between the final visible Stage card and the bottom navigation.

At the bottom of Stage Select, use a centered, balanced navigation group with:
- **Back**
- **Book**

The global Book button opens the full Creature compendium and allows the player to browse across Stage sections.

Prototype 1 requires only the Lake card, but the layout should be structurally ready for multiple simultaneously available Stages.

### In-Stage idle UI

While READY to Cast, keep the Stage interface minimal:
- Book
- Settings
- Circular `CAST` button

Additional permanent clutter should be avoided.

### Fight UI

During a Fight:
- The compact Fight HUD becomes the primary interface.
- Directional cue, Tension, Catch Progress, and circular `REEL` control remain grouped together.
- The complete Fight control cluster is **horizontally centered** on the screen.
- Directional cue, Tension Bar, Catch Progress Bar, and circular `REEL` button share one center axis.
- The `REEL` button sits a little lower beneath the meter stack to preserve separation and thumb comfort.
- Slight overlap with the Player Character is acceptable if needed to maintain true center alignment.
- Book is unavailable during the encounter.
- Settings remains an unobtrusive pause/access route if retained on screen.
- Nonessential UI should visually step back.

### Book

The Book is a **global compendium with Stage-based sections**.

The interface allows the player to move between Stage sections such as:
- Lake
- Swamp
- Frozen Waters

Each Stage section contains its own Creature grid and completion count.

For the Lake:
- Seven Creature slots
- Undiscovered Creatures use silhouettes and `???`
- Discovered Creatures show artwork and name
- Selecting a discovered entry may open a more detailed view

Navigation behavior:
- Open from **Stage Select Book** -> full Book, last viewed Stage section or Lake by default
- Open from a **Stage-card Book shortcut** -> that Stage section
- Open from **inside a Stage** -> current Stage section

Prototype 1 only requires the European Perch to transition from hidden to revealed.

### Settings

Prototype 1 Settings should remain simple and contain:
- Music volume
- SFX volume
- Haptics on / off
- Fullscreen control

A destructive Reset Save option may be added later but is not required for Prototype 1.

Opening Settings during gameplay pauses the active encounter.

### Catch Reveal

Catch Reveal should temporarily command the player's attention.

Prototype 1:
- European Perch artwork
- `European Perch`
- `New Book Entry` on first catch
- Simple **Continue** action

Repeat catches omit the `New Book Entry` treatment.

The reveal is dismissed manually rather than disappearing automatically.

### Transitions

Menu and screen transitions should be short and restrained:
- brief fades
- subtle slides
- simple Stage-entry transitions

Avoid flashy transitions that make repeated fishing loops feel slow.

The transition from Stage Select into a Stage should feel like entering the fishing location rather than opening another app page.

### Mobile ergonomics and readability

- Respect safe areas and system gesture regions.
- Keep critical controls within comfortable thumb reach.
- Do not communicate danger through color alone.
- Tension and other warnings should also use value, shape, motion, SFX, and optional haptics.
- Stage artwork should remain readable behind UI at common portrait phone and small-tablet sizes.
